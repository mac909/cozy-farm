# Cozy Farm

A cozy 2D pixel-art farming game for a couple to play together: real time, in the browser, on laptops and phones, connected through Tailscale. Seaside village setting. One developer (a web dev) builds and maintains it with Claude doing most of the coding; the other player only plays.

Read [docs/DESIGN.md](docs/DESIGN.md) (what the game is and the decisions so far) and [docs/ROADMAP.md](docs/ROADMAP.md) (what's done and what's next) before starting a feature.

## How we work

- Claude writes most of the code. The developer steers, tests, and judges how things feel. Briefly explain non-obvious decisions in chat.
- One feature per session. Use plan mode for anything bigger than a small change.
- Before calling a feature done: `npm run typecheck`, `npm test`, and check it in the browser pane. Two tabs means two players; open the second at http://127.0.0.1:5173 so it keeps its own saved name and look. The pane shows one tab at a time and hidden tabs pause their game loop, so check the other tab's view after switching to it. Use the mobile viewport to check the touch layout. If the pane is hidden, the game's animation frames stop; add `?loop=timer` to the URL (dev only) to run it on timers instead.
- When a design decision is made or changed, update docs/DESIGN.md. Tick items off in docs/ROADMAP.md as they land.
- Commit after each working step, with a message that says what changed for the players.
- `main` is backed up to the private GitHub repo mac909/cozy-farm (`origin`). After committing or merging on `main`, run `git push`. Never push session or worktree branches, and never make the repo public: it has the developer's network details, and asset licenses may forbid redistribution.

## Stack

- **Client** (`client/`): Phaser 3 + TypeScript, bundled by Vite.
- **Server** (`server/`): Colyseus 0.16 on Node, run with tsx. Serves the built client and hosts the one shared world room.
- **Shared** (`shared/`): sync schema, map data, constants, and pure game logic used by both sides.
- **Tests**: Vitest, mainly for `shared/`.
- **Hosting**: one Docker container on the developer's Windows PC. Players connect through Tailscale (see Network below).

## Network

- The real farm's address is **https://msi.tailbddd5f.ts.net** (`msi` is the PC in the tailnet `tailbddd5f.ts.net`). `tailscale serve` on the PC publishes it: Tailscale holds the HTTPS certificate and forwards to the farm on localhost:8080, WebSockets included (the client switches to `wss:` by itself). The setting was made with `--bg`, so it lasts across reboots. `tailscale serve status` shows it; `tailscale serve reset` removes it. HTTPS certificates are switched on for the tailnet on the admin console's DNS page.
- The old address still works: **http://100.82.139.111:8080** (the PC's Tailscale IP). Always include `http://` with it: browsers otherwise try HTTPS, which that address doesn't serve, and fail.
- Players install the game on their phone's home screen from the HTTPS address (steps in README.md). It then opens full screen, using `client/public/manifest.webmanifest`, the icons next to it, and the Apple meta tags in `client/index.html`. There's no service worker; the game needs the server anyway. A home-screen app keeps its own storage, so it asks for a name and look again the first time it opens. Manifest changes reach phones with the next `npm run farm:up`.
- Every device needs the Tailscale app switched on. It works at home and away.
- The home router (Spectrum) blocks Wi-Fi devices from reaching each other, so `192.168.1.x` addresses don't work from phones. Tailscale goes through its relay instead (about 50–150 ms).
- Windows Firewall: the Wi-Fi and Tailscale networks are set to Private, the "Docker Desktop Backend" rule allows Private, and a "Cozy Farm (port 8080)" rule allows the local subnet. Changing firewall rules needs an admin window, so the developer runs those commands.
- Security Center still lists an old, uninstalled Norton as the firewall. Ignore it; Windows Firewall is the one in effect.

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Game server on :2567 and Vite on :5173. Open http://localhost:5173. It saves to `data-dev/` (never the real farm). In the browser console, `dev.nextDay()` (a whole night, with the fade and the morning card), `dev.setTime("23:50")` and `dev.addCoins(100)` skip ahead for testing, `dev.give()` fills the Village Board's open step (or, once the lighthouse is done, your own porch; `dev.give("house2:porch")` for a particular one; the cheer comes on every screen) and `dev.build()` builds what's gathered now instead of overnight, `dev.xp("fishing", 100)` adds experience to one of your skills (levels, gifts and badges come as in play), `dev.season("winter")` makes today the first day of a season (`dev.season("spring", 14)` its last; the seasons begin if they haven't), `dev.item("driftwood", 10)` puts things in your bag, and `dev.goTo("dock")` (or `"dockEnd"`, `"beach"`, `"meadow"`, `"tent"`, `"board"`, `"point"`, `"pointEnd"`, `"gardenShop"`, `"boardwalk"`, or a column and row) moves your own character there. | `npm run dev:fresh` | Deletes the dev save (`data-dev/`) and starts `npm run dev` with a brand-new world |
| `npm test` | Unit tests |
| `npm run typecheck` | TypeScript check across client, server, and shared |
| `npm run build` | Builds the client into `dist/client` |
| `npm run sprites` | Checks `tools/sprites/` and re-renders our own sprites into `client/public/assets/custom/` |
| `npm run farm:up` | Rebuilds and (re)starts the **real farm** container on :8080 |
| `npm run farm:logs` / `npm run farm:down` | Follow its logs / stop it |

## Where things live

- **Server messages:** one file per feature in `server/src/rooms/` (`farming.ts`, `bag.ts`, `crate.ts`, `shop.ts` for the seed stand, the general store and the garden shop (seeds, and `upgradeTool`), `night.ts` for the tent, beds and the night, `houses.ts` for moving in, `decor.ts` for furniture and decorations, `beach.ts` for picking up finds and driftwood, `village.ts` for giving at the Village Board (and "climb", the view), `fishing.ts` for casting and landing, `progress.ts` for skills and badges (every deed that counts goes through its `credit`), `bugs.ts` for the meadow's bugs, `collection.ts` for announcing what's new in the book, `dev.ts`), each registered with one line in `FarmRoom.ts`. Handlers check types and bounds, then call the pure rules in `shared/` (`farming/actions.ts`, `economy/trade.ts`, `world/night.ts`, `world/bedtime.ts`, `decor/`) and apply the result with `room.change(world)`. Trades at a place go through `rooms/trade.ts` (are you next to it, awake?). Message types are in `shared/messages.ts`, one section per feature.
- **Network state:** `shared/schema.ts`, copied from the plain `World` by `shared/stateSync.ts`. The save (`server/src/persistence/worldSave.ts`) is written from the `World`, never from the schema.
- **Cards over the game** (morning, bed banner, bag, crate, seed stand, tips) are HTML, built on `client/src/ui/panel.ts` and `panel.css`, each with its own CSS file. `WorldScene.openPanel()` opens one at a time and lets go of held keys when they open and close (a card keeps key releases away from the game).
- **Places** (tent, crate, seed stand, store, the Village Board) are rectangles in the map's `Objects` layer; `shared/world/places.ts` says who's near which. Doors, the way out of a room and beds are "spots" too (`client/src/world/Homes.ts`), and `chooseAction` in `shared/farming/actions.ts` turns whatever you're next to into the Action button's job; `Farming.ts` carries it out.
- **Houses:** `shared/world/houses.ts` (doors, rooms, who's where), `shared/decor/` (pieces and where they fit, moving in, placing, beds), `client/src/world/Homes.ts` (cottages, signs, rooms, the camera), `client/src/world/Arrange.ts` (arrange mode). Furniture is data in `shared/content/furniture.ts`, its pictures in `client/src/art/furnitureArt.ts`, the store's shelves in `shared/content/generalStore.ts`, and each cottage's look in `shared/content/houses.ts`.
- **Old saves:** `server/src/persistence/fixtures/world-v<N>.json`, one per save version, all loaded at today's version by `oldSaves.test.ts`. Never edit one; a new version adds a new fixture. Today's version is 6 (Milestone 8: `yearStart`, the day spring first came; version 5 was Milestone 7's `progress` for each farmer, house upgrades among the projects and regrown crops marked; version 4 Milestone 6's village and what's lying about; version 3 Milestone 5's world seed, beach, collection book and rods).
- **Collecting (Milestone 5):** the rules are in `shared/`: `fishing/fishing.ts` (the minigame) and `fishing/spots.ts` (where a line goes in), `beachcombing/beachcombing.ts` and `beachcombing/tide.ts` (what washes up each morning), `bugs/meadow.ts` (which bugs are out, and their flutter), `collection/collection.ts` (the book) and `collection/collect.ts` (bag and book together), and `world/terrain.ts` (water, dock, beach sand and meadow grass, read from the map's Ground terrain). The data is `shared/content/fish.ts`, `beachFinds.ts` and `bugs.ts`. On screen: `client/src/world/Fishing.ts` (the rod, line, bobber and minigame), `Beach.ts`, `Meadow.ts`, and `client/src/ui/BookPanel.ts`, `Celebration.ts` and `FishingStrip.ts`, with their words in `bookText.ts` and `fishingText.ts`.
- **The village (Milestone 6):** the data is `shared/content/projects.ts` (projects, steps, needs, Marlow's lines for each), `keeper.ts` (his name, the village's name `VILLAGE_NAME`, his first note and small talk) and `forage.ts` (driftwood and branches); materials are items in `items.ts`. The rules: `shared/village/village.ts` (the saved shape), `village/projects.ts` (what's up on the board, giving, building overnight, Marlow's luck), `village/built.ts` (`builtThings`: the built names the map understands), `foraging/forage.ts` (the morning's driftwood and branches, picking them up), `world/gates.ts` (`mapFor`: the map as of today), `world/today.ts` (`todayFor`: that map plus the reachable beach, woods and meadow, worked out once per set of built things), `world/keeper.ts` (where Marlow is), `decor/makeRoom.ts` (decorations out of the way of something built), and `world/night.ts` (`endNight` builds, brings Marlow and the storm; `startOfServer` the same at start-up). ## Editing the map

The village is a [Tiled](https://www.mapeditor.org/) map, `shared/world/village.json`. The client draws it, and the server reads its size, spawn point, collisions and farmland from the same file.

- Install Tiled (free): `winget install Tiled.Tiled`. Open `shared/world/village.json` and save with Ctrl+S; it stays JSON.
- Layers, top to bottom:
  - `Above`: tree tops and palm fronds, drawn over the characters. Any tile layer with the bool property `aboveCharacters` set does this.
  - `Decor` (trunks, fence, dock, boat), `Details` (flowers, grass tufts), `Ground` (grass, sand, sea). Every other tile layer is drawn too, under the characters, in Tiled's order.
  - `Collision`, hidden in the game: paint the red marker wherever nobody can walk. Only feet collide, so block a tree's trunk row, not its top.
  - `Farmland`, hidden in the game: the green marker where farming is allowed.
  - `Objects`, found by name: the `spawn` point (also where you wake up, in front of the tent's door); rectangles for the `shippingCrate`, the `tent` (48×48, the pack's camp tent), the `seedStand` and the `store` (64×48), which the game draws at those spots; `deepWater` rectangles (the deep water off the dock's end, where the big fish bite); and `ripple` points on the sea. `Collision` is painted under the bottom row of each, so you can walk behind their tops. Moving one means moving its rectangle and its `Collision` together.
  - The Ground layer's terrain (grass, sand, sea) matters to the game too (`shared/world/terrain.ts`): you can fish into sea (or the foam along the shore) that has `Collision` and nothing drawn on it; the dock is walkable sea; finds wash up on plain sand within 5 tiles of the water with nothing on `Decor` or `Details`; bugs flutter over plain walkable grass outside the farm field. So paint beach and meadow with the terrain brush.
  - The village's objects (Milestone 6): the `board` rectangle (2 × 2, right of the seed stand, `needs: keeper`), the `lighthouse` rectangle (3 × 6 on the point; the game draws it, its door is the middle of its bottom row, with `Collision` under that row), `pointWater` rectangles (`needs: lighthouse`: the point's night fishing), `woods` rectangles (where branches fall, round the meadow's trees), and Marlow's points `keeperDay`, `keeperEvening`, `keeperNight` and `keeperEveningLit`, each with a string property `facing`.
  - Cottages: a `house1` rectangle (64×48, the door in its bottom row, at the column `shared/content/houses.ts` says) and its room, an `interior1` rectangle, and so on for `house2`. The rooms are drawn below the sea, in the bottom rows of the map that the camera never shows from outside: walls (`TilesetWallSimple`) on `Decor` with `Collision` under them, the floor on `Ground`, the dark `TilesetWallSimple` tile everywhere round them, and a gap with a mat in the middle of the bottom wall as the way out. Furniture is saved relative to the room's floor, so a room can move. A new cottage needs both rectangles; give it a line in `houses.ts` for its look.
- Terrain brush: open View → Views and Toolbars → Terrain Sets, pick "Beach" in `beach-terrain`, and paint Grass, Sand or Sea; Tiled picks the edge tiles. Keep sand between grass and sea: there are no grass-to-sea tiles.
- Anything new that should block the way (a tree, a fence) also needs `Collision` painted under it.
- **Locked and unlocked (Milestone 6):** things come and go as the village is built. A built name is `keeper` (Marlow is here), a project (`lighthouse`, from when it opens: the lamp is lit at dusk; `gardenShop`, Milestone 8) or one of its steps (`lighthouse/path`, `lighthouse/stairs`, `lighthouse/lamp`; `gardenShop/boardwalk`, `gardenShop/shop`, `gardenShop/drawers`), from the morning it's built, or a house upgrade (`house1:porch`, Milestone 7); `bridge` is Milestone 9's. A shown art layer counts as something drawn there (nothing washes up on the boardwalk's planks). Any tile layer may have a string property `shownFrom` (drawn and in effect once that's built) or `shownUntil` (until it is). A layer named `Collision …` (`Collision brambles`) or `Farmland …` counts as walls or farmland while it's in effect; give a gated wall a string property `hint` (a hint reason in `shared/farming/actions.ts`, like `brambles`) and facing it says that. Objects may have a string property `needs`. `map.test.ts` checks every name is one the game knows, and what can be reached with nothing and with everything built.
- **The garden shop and the boardwalk (Milestone 8):** a `gardenShop` rectangle (4 × 3: the shop and its potting bench, the door in its second column, `Collision` under its bottom row) where the clump of bushes stood, drawn in code (boarded, patched, open, bunting on its opening day); its Action wakes up once `gardenShop` is built. The `Boardwalk` layer (`shownFrom: gardenShop/boardwalk`) lays the dock's planks along rows 17–18 from the market to the inlet. A `keeperOpening` point (string properties `project: gardenShop`, `facing`, `needs: gardenShop`) is where Marlow stands the day it opens; later projects add their own. The `seasonal-trees` tileset isn't painted anywhere: the game swaps the round trees to it in autumn (`client/src/art/seasonArt.ts` says which tiles become which each season, so a new tree painted with the pack's round, blossom or pine tiles changes with the seasons by itself).
- **Porches (Milestone 7):** each cottage has a `Collision porch house1` layer (`shownFrom: house1:porch`) painting the row in front of it where the lantern's post and the bench stand (the columns `porch` gives in `shared/content/houses.ts`; `map.test.ts` checks they match). The porch itself is drawn in code there. A new cottage needs one too.
- **Growing the map:** only ever add columns on the right or rows at the bottom. Saves hold farm tiles, decorations, finds and positions in map tiles, so growing left or up would move them; `map.test.ts` holds the Milestone 5 map's farm field, places, rooms and walkable tiles in place. Anything newly built over a decoration moves the decoration aside (`makeRoom`), a decoration left where an update has since put a wall moves aside when the server starts (`settleDecorations`), and a player rejoining somewhere no longer walkable starts at the spawn point.
- New tilesets: 16×16 tiles, the image inside `client/public/assets/`, and embedded in the map (tick "Embed in map" when creating it, or press Embed Tileset in the Tilesets panel), because Phaser can't read separate `.tsx` files. Keep Map → Map Properties → Tile Layer Format on CSV.
- Run `npm test` after saving: it checks the map loads, the spawn is walkable and in front of the tent, the whole farm field, the shipping crate, the tent, the seed stand, the store and every cottage's door can be reached, each room has a walkable floor and a way out but can't be walked into from the village, and every tileset image exists. `npm run dev` picks up the change when the page reloads.

## Rules

- **The server owns the world.** Anything shared (crops, items, money, furniture, the clock) changes only in the server room, in response to client messages. Clients send intents ("water tile 12,4"), not results. One exception: each client moves its own character locally and reports its position.
- **Game rules are pure functions in `shared/`**, with tests and no Phaser or Colyseus imports. Rooms and scenes call them.
- **Content is data.** Define crops, items, furniture, critters, and maps in data files under `shared/`, never inline in logic.
- **Touch first.** Every action must work with one thumb on a phone as well as with a keyboard. HUD and controls go in `UIScene` (camera zoom 1). The world goes in `WorldScene` (integer zoom only, so the pixels stay crisp).
- **Pixel art:** 16×16 tiles, `pixelArt: true`. The art is the Ninja Adventure pack (CC0) in `client/public/assets/ninja-adventure/`, plus our own sprites in `client/public/assets/custom/`, drawn as data in `tools/sprites/` (see its README for style rules and sheet layouts). `client/src/art/assets.ts` loads it all and names the texture keys; character sheets are 4 columns (facing down, up, left, right) with the walk cycle in rows 0–3. The village is a Tiled map (see Editing the map below). The dev-only page `/art-preview.html` shows our sprites next to the pack. Need more from the pack? It's free on itch.io (link in `CREDITS.md`); copy in only the files the game uses.
- **Protect the real farm.** It runs in Docker on :8080, with saves in the `farm-data` volume. Never run `docker compose down -v`, never delete that volume, and never point dev at it. Dev uses its own ports and, from Milestone 2, its own `data-dev/` folder. Test the farm scripts by pointing their `-Container`, `-Volume` and `-Image` options at throwaway ones.
- **Saves are versioned** (from Milestone 2). Every save carries a `version`. Changing the format means adding a migration, never breaking old saves. The save layer is `server/src/persistence/`: SQLite through Node's built-in `node:sqlite`, in the folder named by `DATA_DIR` (`data-dev/` in dev, the farm-data volume in Docker). The world's save format and its migrations are in `worldSave.ts`. If a save won't load, the server must stop rather than start a fresh world over it.
- **Two trusted players.** No accounts, passwords, or anti-cheat. Validate messages only enough to avoid crashes or corrupt state (types, bounds).
- **Free only.** No paid services or assets. Asset licenses must allow this use; record every pack and its license in `client/public/assets/CREDITS.md`.
- Keep dependencies few. Mention any new one in chat and say why.
- Colyseus schemas use decorators, which need `experimentalDecorators: true` and `useDefineForClassFields: false` in tsconfig. Don't change those.
